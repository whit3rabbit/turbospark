# S3 Speech Tokenizer (CosyVoice / FunAudioLLM)

S3 is the discrete speech tokenizer family developed for CosyVoice and FunAudioLLM. It converts log-mel spectrogram features into discrete token streams for generative speech modeling.

## Upstream References and URLs

- **Reference implementation**: [`mlx_audio/codec/models/s3/`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/codec/models/s3) at mlx-audio `e1b19b9054bf163f5d812221a54fcc346f1890e9` (v0.5.7).
- **Upstream repositories**: FunAudioLLM CosyVoice / SenseVoice S3Tokenizer checkpoints.

## Architecture and Generations

### S3Tokenizer v1
- **Frontend**: Whisper-style convolutional downsampler with two strided Conv1d blocks mapping 128 mel bins to hidden state dimension 1280.
- **Backbone**: Sinusoidal positional embeddings followed by multi-head self-attention Transformer blocks.
- **Quantizer**: Vector quantization using an Euclidean codebook over L2-normalized frame vectors (`n_codebook_size = 4096`).
- **Rates**: Available in 25 Hz (`speech_tokenizer_v1_25hz`, stride 2) and 50 Hz (`speech_tokenizer_v1`, stride 1) profiles.

### S3Tokenizer v2
- **Frontend**: Two strided Conv1d blocks with 2x temporal reduction.
- **Backbone**: Multi-head attention with NeoX rotary positional embeddings (RoPE, dimension 64) and an integrated Feedforward Sequential Memory Network (FSMN) temporal branch.
- **Quantizer**: Finite Scalar Quantization (FSQ) projecting hidden states to 8 channels with ternary levels (-1, 0, 1), resulting in 3^8 = 6561 discrete code indices.
- **Sliding-window support**: Audio exceeding 30 seconds (3000 mel frames) processes through sliding windows (2600-frame stride, 400-frame overlap) with half-overlap token merging.

## Upstream Defect and Parameter Handling

In upstream mlx-audio, v1's codebook is stored on `VectorQuantization._codebook`, an underscore-private attribute that MLX parameter serialization skips. The Rust weight loader reads the codebook from `quantizer.embed` (and aliases `quantizer._codebook.embed` / `quantizer.codebook.embed`), guaranteeing deterministic codebook loading across PyTorch and converted checkpoints.

## Verification

Parity is established against pinned Python MLX fixtures generated by `tools/gen_s3_fixtures.py`:

```sh
cargo test -p turbospark-audio --lib codec::s3
```

Real checkpoint verification:
```sh
TURBOSPARK_S3_MODEL_DIR=/models/s3-tokenizer \
  cargo test -p turbospark-audio --lib codec::s3::tests::real_checkpoint_gate -- --ignored
```
