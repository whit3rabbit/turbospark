# DACVAE (VAE-Style Continuous Audio Codec)

DACVAE is the continuous (VAE) audio codec built for SAM-Audio: a
DAC-shaped weight-norm conv encoder, a projection to mean/logvar
halves where the mean is the transmitted latent, and a mirrored
transposed-conv decoder with tanh output. Unlike DAC there are no
discrete codes; the latent is continuous.

## Model Overview

```text
Mono PCM (B, T, 1) channels-last
   |
   v
Right-pad to a multiple of hop_length
   |
   v
Encoder: WN-Conv1d(1 -> d, k7, pad 3)
   -> [EncoderBlock x |rates|]: 3x ResidualUnit(d 1, 3, 9) + Snake
      + strided WN-Conv1d(k = 2s, pad s//2, static)
   -> Snake -> WN-Conv1d(d -> latent, k3, pad 1)
   |
   v
QuantizerInProj (kernel-1 WN conv latent -> 2 * codebook_dim);
the mean half (first codebook_dim channels) is the latent
   |
   v  (B, codebook_dim, frames)
QuantizerOutProj (kernel-1 WN conv codebook_dim -> latent)
   |
   v
Decoder: WN-Conv1d(latent -> d, k7, pad 3)
   -> [DecoderBlock x |rates|]: Snake + transposed WN-Conv(k = 2s,
      padding (s+1)//2) + 3x ResidualUnit(d 1, 3, 9)
   -> Snake -> WN-Conv1d(d -> 1, k7, pad 3) -> tanh
```

### Architecture Specifications

| Property | Value |
|---|---|
| Default geometry | encoder 64, rates [2, 8, 10, 12], latent 1024, decoder 1536, rates [12, 10, 8, 2] |
| Sample rate | 48 kHz |
| Hop length | 1920 |
| Latent | continuous, codebook_dim 128 per frame |
| Batch | 1 (crate convention) |

## Scope and Reference Deviations

1. **Watermarking subsystem not ported.** The Decoder carries a
   Watermarker (LSTM message encoder/decoder, MsgProcessor) used only
   by `decode_with_watermark`; the batch `DACVAE.decode` contract never
   touches it. The checkpoint's watermark tensors are simply unused by
   the Rust loader.
2. **Static symmetric padding.** Unlike SNAC/DAC's extra-padding
   scheme, dacvae's pad_mode "none" computes fixed MLX paddings
   (`(K - stride) * dilation // 2` for convs, `(stride + 1) // 2` for
   transposed convs) -- the ports use ops::conv1d / conv_transpose1d
   symmetric padding directly, no unpad step.
3. **Chunked decode** (`_decode_chunked` with crossfade) is out of
   scope; callers chunk latents themselves if needed.
