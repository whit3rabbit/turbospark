# Spark BiCodec (decode direction)

Decoder for the Spark-TTS 0.5B BiCodec audio tokenizer: semantic +
global tokens back to a 16 kHz waveform. Reference:
[`mlx_audio/tts/models/spark/`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/tts/models/spark)
(bicodec.py, modules/) at mlx-audio
[`e1b19b9054bf163f5d812221a54fcc346f1890e9`](https://github.com/Blaizzy/mlx-audio/commit/e1b19b9054bf163f5d812221a54fcc346f1890e9).
The TTS family consumes exactly `BiCodec.detokenize`; the encode
direction is a separate wav2vec2-based pipeline and stays open (see
below).

## Architecture (decode path)

```text
semantic tokens [T]  ->  FactorizedVectorQuantize.detokenize
    codebook lookup [T, codebook_dim=8]
    kernel-1 weight-norm out projection -> z_q [1024, T]
global tokens [32]   ->  SpeakerEncoder.detokenize
    implicit FSQ codebook (levels [4]*6, no learned weights)
    project_out Linear(6 -> 128)
    dim-major flatten to [4096], project Linear(4096 -> 1024) -> d_vector
z_q + d_vector:
    prenet (feat Decoder): linear_pre, [SamplingBlock(ratio 1) +
    2-layer Vocos backbone] x2, conditioned 12-layer Vocos backbone
    (AdaLayerNorm on the d_vector), output linear
    x = x + d_vector[..., None]
    WaveGenerator (DAC-style): stem WNConv1d(k7), four
    snake/conv-transpose/residual-unit blocks at rates 8, 5, 4, 2
    (320x total), snake + WNConv1d(k7) + tanh -> waveform [320 * T]
```

## Reference behaviors pinned here

- The `SamplingBlock` identity branch (both scales 1) has no weights
  and multiplies the signal by 3: the three skip adds
  (`conv_res + skip1_res + skip2_res`) all carry the input. The
  published prenet `sample_ratios [1, 1]` makes this load-bearing.
- The prenet output width, the WaveGenerator input width, and the
  speaker out_dim are 1024 together; the config gate rejects the
  mlx-audio dataclass defaults (256/512) because the reference
  `x + d_vector[..., None]` broadcast cannot run there.
- `prenet.vocos_backbone` AdaLayerNorm checkpoints store LEARNED
  scale/shift weights that override the vocos init (ones/zeros); the
  vocos checkpoints the [vocos](../vocos) port targets omit those
  tensors, so the loader keeps both paths.
- Empty semantic tokens are rejected: the reference zero-frame
  placeholder shape never survives its own prenet transpose, so the
  observable upstream behavior is an error, not audio.
- Checkpoint layouts: the published module tree stores MLX conv
  layouts (`[out, K, in]`, `block.layers.` names); raw torch-layout
  exports (`[out, in, K]`, `block.` names) load through the reference
  sanitize transposes. Every conv loader accepts both.

## Verification

Fixtures: `testdata/spark_bicodec/`, regenerated by
`tools/gen_spark_bicodec_fixtures.py` against the pinned commit (seeded,
no network; the reference module tree built at tiny dims: quantizer
input 16 over a 64x4 codebook, FSQ levels [3, 3, 3, 3] with 4 global
tokens, 2-layer Vocos prenet at width 12, WaveGenerator channels 8 with
two stride-2 blocks). The detokenize cases gate at 2e-4 absolute;
measured max diff 8.9e-8. Negative tests: codebook and FSQ range
checks, token-count checks, and the config broadcast gate.

## Open items

- Encode direction (`BiCodec.tokenize`): Wav2Vec2-large-xlsr-53
  features (hidden states 11 + 14 + 16 over 3), the BiCodec Encoder,
  the factorized quantizer argmin assignment, and the ECAPA-TDNN +
  Perceiver + FSQ speaker tokenize path. The Rust `stt::wav2vec`
  backbone may cover the feature extractor; the voice-clone prompt
  needs it. Until then the spark family takes caller-supplied global
  and semantic token ids (see the family README).
- Prenet `sample_ratios` above 1 (the unported sampling-block conv
  paths) are rejected by the config gate; the published decode path
  uses [1, 1].
- Real-checkpoint gate (SparkAudio/Spark-TTS-0.5B BiCodec) not run;
  fixtures are seeded tiny instances.
