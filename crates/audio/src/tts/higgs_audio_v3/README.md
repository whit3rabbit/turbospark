# Higgs Audio v3 TTS family

Port of `mlx_audio/tts/models/higgs_audio_v3/` (model.py, config.py,
generation.py, prompt.py) at mlx-audio
[`e1b19b9054bf163f5d812221a54fcc346f1890e9`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/tts/models/higgs_audio_v3)
(mlx 0.32.3), pinned by `crates/audio/testdata/tts_higgs_audio_v3/`
(generated by `tools/gen_higgs_audio_v3_fixtures.py`).

## Architecture

A qwen3 dense backbone (shared `crate::lm` engine) whose generation never
reads the text head: every step emits one codebook vector of
`audio_num_codebooks` classes drawn from the audio logits, which are the
FUSED `multimodal_embedding` table read as a linear (`as_linear`) and
reshaped to `[K, V]`. The same table is the audio input embedding: a
frame's codes shift by per-codebook offsets (`codebook k` rides rows
`k * codebook_size + code`) and their rows sum. Unlike the v2 family
(`../higgs_audio`), the per-codebook stride is exactly `codebook_size`
(defaults 1026, with BOC 1024 / EOC 1025 as ordinary in-vocabulary
sentinel classes), there is no dual-FFN audio path, no separate audio
head, and no RAS warmup logic.

Generation (reference `generate`, batch of one):

1. The prompt splices text token rows with ALREADY-delayed reference
   audio rows (prompt.py `HiggsAudioV3PromptBuilder`): `<|tts|>`, per
   reference the optional `<|ref_text|>` transcript plus `<|ref_audio|>`
   and its placeholder rows, then `<|text|>` target `<|audio|>`.
2. One prefill over the prompt embeddings; then per step the `[K, V]`
   audio logits feed the SGLang-style sampler state machine: a `K`-frame
   ramp-in forces the not-yet-active codebook tail to BOC, the first
   codebook EOC sets a `K - 2` frame countdown, and its expiry ends the
   loop.
3. `reverse_delay_pattern` takes the diagonal of the delayed rows back
   to raw `[T, K]` codes; the codec decodes them (no clipping, unlike
   v2: sampled sentinel values ride into the codec, whose v3 codebooks
   cover them), and the shared v2 edge fades apply
   (`crate::tts::higgs_audio::apply_fades`).

## Verification

Fixture protocol identical to the other LM-backed families:
`tools/gen_higgs_audio_v3_fixtures.py` builds the true v3 `Model` at tiny
seeded dims (2 qwen3 layers, hidden 32, head_dim 8, text vocab 64, 4
codebooks of 10 with BOC 8 / EOC 9, F16-stored weights reloaded upcast so
the traces record exactly what the Rust f32 path reads), runs the true
prompt builder, `step` sampler, and a tiny seeded codec (4 RVQ books, the
real RVQ-sum/fc2/acoustic-decoder stacks), and records into
`testdata/tts_higgs_audio_v3/`:

- `generate/`: the pinned voice-clone prompt (special ids, mock
  tokenizations, delayed reference codes, prompt token ids with
  placeholders, full embedding block), a forward pin (last hidden row
  and audio logits), and two greedy end-to-end scenarios (EOC ramp stop,
  max-steps stop) with raw frames, aligned codes, stop reasons, and the
  faded waveforms.
- `delay/`: `apply_delay_pattern` / `reverse_delay_pattern` on fixed id
  grids.
- `sampling/`: greedy argmax rows, the top-k and top-p masked SCALED
  logits through the reference `_apply_top_k` / `_apply_top_p` links
  (log-softmax, filter, map the masked entries back), plus one
  categorical record for reference only.
- `manifest.json`: sha256 digests, backbone seed 9, EOC amplification
  1.8.

Measured parity on the frozen fixtures (gates in `tests.rs`): prompt
embeddings and every delay/sampler integer trace exact; last hidden row
2.4e-7 and audio logits 3.6e-7 (gate 2e-5); waveforms at or below
3.8e-8 (gate 1e-6). Config defaults, `audio_encoder_config` fallbacks,
and the `rope_parameters.rope_theta` alias are pinned by a dedicated
test.

Mutation checks: dropping the ramp-in BOC forcing, the EOC countdown, or
the fused-table offset multiply each move the greedy frames off the
fixture ids (the scenarios run through the EOC ramp, the max-steps cap,
and the codec decode end to end).

## Deviations and scope

- Batch size 1, non-streaming: the reference `continuous_batching.py`
  batch engine (padded prompts, `BatchKVCache`, `filter`) is out of
  scope; the single-prompt `generate` is the ported path.
- Caller-owned text tokenization: the reference loads the checkpoint
  `tokenizer.json` in `post_load_hook` and validates the four required
  specials plus the optional `<|ref_text|>`; the Rust `PromptBuilder`
  takes the resolved ids. Reference-audio encoding is out of contract
  (the codec `encode` needs the wav2vec2 semantic tower), so reference
  codes arrive precomputed and the family applies the delay pattern.
- Sampled (temperature > 1e-5, top_k != 1) draws use the crate-local
  threefry RNG in row-major per-step order, so a sampled Rust run
  diverges token-by-token from mlx at the same seed; the filter masks
  and greedy runs are pinned exactly. The greedy shortcuts match the
  reference exactly (temperature <= 1e-5 OR top_k == 1 -> argmax).
- The reference frame-cap alias resolution (`max_new_tokens` ->
  `max_new_frames` -> `max_tokens` -> 2048) collapses into one
  `GenerateParams::max_new_frames` field (default 2048).
- `use_delay_pattern` and `audio_token_id` are parsed for config parity
  and never read, matching the reference (the delay pattern is
  unconditional in its prompt and decode paths; the placeholder id is a
  prompt-module constant).
- Checkpoint layouts: the loader probes absolute tensor names and
  recognizes the bare module tree (`layers.*` + `embed_tokens`), the
  full-model `model.` save, the MLX-sanitized `backbone.` save, and the
  raw bosonai names (`body.layers.*`, `tied.embedding.text_embedding`,
  `tied.embedding.modality_embeddings.0.embedding`), mirroring the
  reference `sanitize`; the skipped `tied.head.*` and
  `modality_embeddings.0.model.*` tensors are never read. The raw-layout
  embed-table name rides the additive `Backbone::load_with_embed_table`.
  Only the `backbone.` layout is fixture-pinned; the other three ride
  the same probe logic without a fixture.

## Open items

- Real-checkpoint gate (bosonai/higgs-audio-v3-tts-4b or its
  mlx-community conversion) not run: the fixtures are seeded tiny
  instances. The raw-layout loader path in particular has only the
  fixture-pinned module-tree layout behind it.
- Batch generation, streaming, and the `genders`/`speeds`/`pitches`
  argument surface of `batch_generate` remain unported (the reference
  refuses all of them anyway).
