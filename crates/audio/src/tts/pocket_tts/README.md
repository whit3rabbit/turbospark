# Pocket TTS family (Kyutai flow-LM over continuous Mimi latents)

Port of `mlx_audio/tts/models/pocket_tts/` (pocket_tts.py, flow_lm.py,
transformer.py, mlp.py, rope.py, conditioners.py, config.py, utils.py)
at mlx-audio 0.5.7, pinned to
[`e1b19b9054bf163f5d812221a54fcc346f1890e9`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/tts/models/pocket_tts)
(mlx 0.32.3). The reference chains a lookup-table text conditioner, a
streaming transformer over [text embeddings, audio-conditioning rows,
latent rows], and an AdaLN MLP flow net: each step replaces a NaN seed
with the bos latent, projects the previous latent, reads the EOS head
(`score > eos_threshold`, default -4.0), integrates the conditioned flow
from temperature-scaled Gaussian noise (Euler, `lsd_decode_steps`), and
de-normalizes with `emb_std`/`emb_mean` into the Mimi latent. The run
ends `frames_after_eos` steps after the first EOS flag.

Everything is portable single-batch f32: no Metal, no macOS APIs.

## Layout

- `mod.rs`: the nested config (`flow_lm`, `mimi` sections with the
  required fields), the lookup-table conditioner (embedding plus the
  optional output projection), the streaming transformer (fused
  in-projection split into contiguous thirds, interleaved rope over
  head-major buffers, exact-erf gelu, additive causal masks over
  `lm::KvCache` caches), the AdaLN flow net (timestep embedders with
  the ddof=1 sample-variance RMSNorm, adaLN `[SiLU, Linear]`
  modulation, affine-free final norm), the `lsd_decode` Euler
  integrator, `prepare_text_prompt`, and the single-chunk generate loop
  down to the scaled latents.
- `tests.rs`: fixture parity and regressions.

## Verification

Fixtures at `testdata/tts_pocket_tts/`, regenerated by
`tools/gen_pocket_tts_fixtures.py` (run from the mlx-audio checkout
with `../.venv-mlxaudio/bin/python`). The generator builds the true
reference `FlowLMModel` at tiny seeded dims (d_model 32, 2 layers,
4 heads, lookup dim 16 with an output projection, latent dim 8, flow
dim 32 depth 2) with the sentencepiece tokenizer stubbed; the timestep
embedders' derived `freqs` tables keep their true init values. The
generation loop drives the real conditioning prefill, text prefill, and
per-step `_sample_next_latent` chain. Standard-normal draws come from
per-scenario numpy streams and are replayed by the Rust tests; every
EOS decision must hold a margin of 1.0 over the threshold. Cases:
config parsing, the three end-to-end scenarios (default-EOS stop,
max-steps run, 3-step lsd with noise clamping) pinning per-step noise
consumption, transformer output rows (conditioning prefill, text
prefill, then one row per step), latents, scaled decoding-input
latents, EOS scores and flags; the `lsd_decode` trajectory with
per-stage time-embed, adaLN condition, input projection, residual
block, and final-layer traces; and `prepare_text_prompt` string cases.

Measured parity on the frozen fixtures (gate 2e-4): transformer rows,
latents, and flow directions all at or below 3e-6; EOS flags, eos_step,
stop reasons, and normalized prompt strings exact.

## Scope decisions and deviations from the reference

- Batch size 1, non-streaming, single chunk. The multi-chunk
  `split_into_best_sentences` text splitting and the streaming chunk
  loop are out of scope (both operate before tokenization); the cache
  slice/expand helpers are no-ops on the Rust exact-size caches.
- The waveform decode is an open item: the bundled pocket Mimi is a
  continuous-latent streaming autoencoder (Seanet encoder/decoder plus
  projected transformers with streaming conv state) with no Rust port;
  the shared `src/codec/mimi` module is the RVQ codec. This port ends
  at the scaled latents the Mimi decoder would consume.
- Text tokenization is a caller concern (sentencepiece); the caller
  passes token ids. The audio conditioning is likewise caller-owned:
  the reference derives it from a predefined-voice download or a
  reference file through the Mimi encoder and the `speaker_proj_weight`
  projection; the Rust caller supplies the projected conditioning rows.
- The `frames_after_eos` default comes from the chunk's word count via
  `prepare_text_prompt`; the Rust `generate_latents` (without an
  explicit `frames_after_eos`) uses the short-text branch value 3 plus
  2. Callers pass the value from `prepare_text_prompt` for other texts.
- Sampling noise replays recorded standard-normal draws in the
  fixtures; live runs draw from the crate threefry sequence.
