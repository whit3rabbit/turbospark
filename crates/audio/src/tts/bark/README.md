# Bark family (three-stage GPT: semantic, coarse, fine)

Port of `mlx_audio/tts/models/bark/` (bark.py, pipeline.py, isftnet.py)
at mlx-audio 0.5.7, pinned to
[`e1b19b9054bf163f5d812221a54fcc346f1890e9`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/tts/models/bark)
(the recording interpreter's mlx version is in the fixture manifest).
The reference Pipeline runs a semantic GPT (text-conditioned tokens with
a merged 256+256+1 prompt), a coarse GPT (the first two EnCodec codebooks
through sliding windows), and a non-causal fine GPT (the remaining six
codebooks over 1024-row windows), then decodes all eight codebooks
through EnCodec.

Status: landed at the fixture level. Both end-to-end scenarios replay
the recorded reference Pipeline runs exactly on ids and codes and within
the waveform gate; the open item left is a real-checkpoint gate.
Everything is portable single-batch f32.

## Layout

- `mod.rs`: the three stack configs, the causal GPT (token + learned
  position embeddings, merged-context prefill, cached decode, weight-only
  layernorms, fused attention projection split into thirds, gelu MLP),
  the non-causal fine GPT (per-codebook embeddings tied to per-codebook
  heads in the checkpoints, accepted untied too, biased layernorms), the
  pipeline stages (`generate_text_semantic` with the early-stop pad
  token, `generate_coarse` with the semantic-to-coarse window loop,
  `generate_fine` with argmax or sampled fills), and the EnCodec decode.
- `tests.rs`: fixture parity and regressions.

## The learned additive attention mask

The causal blocks pass `attn.bias` - a `[block_size, block_size]`
parameter stored in the checkpoints - straight into
`mx.fast.scaled_dot_product_attention`, which treats float masks as
additive. The checkpoints carry seeded-noise content in that tensor (the
upstream conversion kept the initialized mask as a parameter), so the
effective attention is NOT causal: every key participates with an
additive per-(query, key) term. The Rust block loads the tensor and adds
`mask[offset + row][j]` over the whole buffer. The fine stack's
`NonCausalSelfAttention` passes no mask at all, so its key range is the
full window too - an earlier Rust revision bounded it causally, which
the fixtures now pin as wrong (below).

## Scope decisions and deviations from the reference

- Batch size 1, non-streaming, no voice prompt: the `.npz` history
  arrays are caller-owned and accepted as optional slices; the recorded
  fixtures run the no-history path.
- Text tokenization is a caller concern (the reference loads a BERT
  tokenizer); the caller passes raw text token ids.
- The reference's `continue`-style tail handling in the coarse window
  loop is expressed as a break (identical observable behavior).
- The categorical draws for the semantic, coarse, and fine stages take
  an injectable `draw` callback over the temperature-scaled slice; live
  callers draw categorically from the crate threefry sequence, and the
  fixtures replay an inverse-CDF stand-in.
- The pipeline path forwards `use_kv_caching` positionally into
  `generate_coarse`'s `max_coarse_history` slot in the reference, so
  `Model::generate` pins `max_coarse_history = 1`, the default 60-token
  sliding window, and no coarse kv cache; direct `generate_coarse`
  callers keep the reference function defaults.

## The fixture recording bug, for the record

The first recording produced a scenario a whose prompt ids said
"hello there" but whose encoded text, semantic tokens, and draw stream
came from "the second one". Root cause: the generator's stage wrappers
were applied cumulatively, so scenario b's run passed through scenario
a's wrappers and overwrote a's captured dict in place; the two scenarios
recorded mutually inconsistent encodings. Spying on
`pipe.tokenizer.encode` during a rebuilt run settled that the pipeline
itself was never at fault - it encodes the raw scenario text in one
call, with no normalization or splitting, so [153, 17, 3] could only be
the stub encoding of scenario b's text. `run_scenario` now derives the
prompt ids from the pipeline's own captured encoding (strip the text
pads and the encoding offset) and builds the prefill probe from those
same ids, so every recorded field of a scenario describes one identical
run by construction.

## Verification

Fixtures at `testdata/tts_bark/`, generated by
`tools/gen_bark_fixtures.py` (run from the mlx-audio checkout with
`PYTHONHASHSEED=0 .venv/bin/python`; the hash seed is pinned because the
seeded weight fill walks the parameter tree in an order that Python hash
randomization perturbs). The generator runs the true reference Pipeline
with `use_kv_caching=True` at tiny seeded dims (2 layers per stack,
n_embd 16, 2 heads; semantic input vocab 129600 so the real
special-token ids fit) over a stub tokenizer and a bark-local tiny
EnCodec with a 1024-entry codebook, records one uniform per sampled row
(resampled until each decision sits over 3e-4 of the adjacent cdf
boundary value, relative), re-records the winner in a fresh interpreter,
and verifies rerun equality and prompt-to-encoding consistency before
writing.

Measured against the frozen fixtures (model seed 7, draw streams
512/1041, semantic 157/391 steps):

- Encoded text ids, semantic tokens, coarse codes, fine codes: exact.
- Uniform stream: fully consumed, draw order semantic steps, coarse
  windows, fine fills.
- Semantic prefill logits: 8.3e-7 max absolute error (gate 1e-4); the
  recorded per-stage chain matches with embeddings and position adds
  exact and block outputs and the final norm within 3.4e-6 (gate 1e-4).
- Decoded waveform: 6.0e-7 (scenario a) and 8.9e-7 (scenario b) max
  absolute error against a 1e-5 gate.
