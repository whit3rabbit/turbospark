# Bark family (three-stage GPT: semantic, coarse, fine)

Port of `mlx_audio/tts/models/bark/` (bark.py, pipeline.py, isftnet.py)
at mlx-audio 0.5.7, pinned to
[`e1b19b9054bf163f5d812221a54fcc346f1890e9`](https://github.com/Blaizzy/mlx-audio/tree/e1b19b9054bf163f5d812221a54fcc346f1890e9/mlx_audio/tts/models/bark)
(mlx 0.32.3). The reference Pipeline runs a semantic GPT
(text-conditioned tokens with a merged 256+256+1 prompt), a coarse GPT
(the first two EnCodec codebooks through sliding windows with a fresh
cache per window), and a non-causal fine GPT (the remaining six
codebooks over 1024-row windows), then decodes all eight codebooks
through EnCodec.

Status: PARTIAL. The semantic prefill path is fixture-verified; the
end-to-end scenario parity is blocked by a reference-side fixture
reproducibility problem (below). Everything is portable single-batch
f32.

## Layout

- `mod.rs`: the three stack configs, the causal GPT (token + learned
  position embeddings, merged-context prefill, cached decode, weight-only
  layernorms, fused attention projection split into thirds, gelu MLP),
  the non-causal fine GPT (per-codebook embeddings tied to per-codebook
  heads in the checkpoints, accepted untied too), the pipeline stages
  (`generate_text_semantic` with the early-stop pad token,
  `generate_coarse` with the semantic-to-coarse window loop,
  `generate_fine` with argmax or sampled fills), and the EnCodec decode.
- `tests.rs`: fixture parity and regressions.

## The learned additive attention mask

The causal blocks pass `attn.bias` - a `[block_size, block_size]`
parameter stored in the checkpoints - straight into
`mx.fast.scaled_dot_product_attention`, which treats float masks as
additive. The checkpoints carry seeded-noise content in that tensor (the
upstream conversion kept the initialized mask as a parameter), so the
effective attention is NOT causal: every key participates with an
additive per-(query, key) term. The Rust block loads the tensor and adds
`mask[offset + row][j]` over the whole buffer; the fine stack's
non-causal attention passes no mask.

## Scope decisions and deviations from the reference

- Batch size 1, non-streaming, no voice prompt: the `.npz` history
  arrays are caller-owned and accepted as optional slices; the recorded
  fixtures run the no-history path.
- Text tokenization is a caller concern (the reference loads a BERT
  tokenizer); the caller passes raw text token ids.
- The reference's `continue`-style tail handling in the coarse window
  loop is expressed as a break (identical observable behavior).
- The categorical draws for the semantic and coarse stages take an
  injectable `draw` callback over the temperature-scaled slice; live
  callers draw categorically from the crate threefry sequence, and the
  fixtures replay an inverse-CDF stand-in.

## Verification

Fixtures at `testdata/tts_bark/`, generated by
`tools/gen_bark_fixtures.py` (run from the mlx-audio checkout with
`PYTHONHASHSEED=0 ../.venv-mlxaudio/bin/python`; the hash seed is pinned
because the seeded weight fill walks the parameter tree in an order that
Python hash randomization perturbs). The generator runs the true
reference Pipeline at tiny seeded dims (2 layers per stack, n_embd 16,
2 heads; semantic input vocab 129600 so the real special-token ids fit)
over a stub tokenizer and a bark-local tiny EnCodec with a 1024-entry
codebook. Verified against the frozen fixtures: the semantic prefill
logits and every per-stage intermediate (merged embeddings, position
adds, per-block outputs, final norm) match within 1e-4, and the prefill
logits row within 2.3e-6.

## Open items (why this is PARTIAL)

- End-to-end scenario parity: the fixture generator's recording run and
  a fresh replay of the same model weights and draw stream disagree
  from the first sampled semantic token (the recording process's own
  prefill logits and its first categorical input differ by up to 0.037,
  while the Rust port matches the recorded prefill logits to 2.3e-6).
  The two end-to-end scenario tests are present but return early unless
  `TURBOSPARK_BARK_E2E` is set; resolving the reference-side recording
  (likely MLX kernel-state accumulation across the generator's seed
  search) unblocks them. The coarse and fine stages are compile-exercised
  and validated for inputs but not yet fixture-pinned end to end.
- Real-checkpoint gate on a bark release (fixtures are seeded tiny
  instances).
- Streaming and the voice-prompt (`ALLOWED_PROMPTS`) path.
