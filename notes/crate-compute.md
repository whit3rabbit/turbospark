## What does turbospark-compute do?

CPU reference kernels: RmsNorm, RoPE (including YaRN), causal attention
(with and without sinks), GDN (gated-DeltaNet), MoE FFN, quantization
(INT4/INT8 affine, 1-bit, 2-bit, GGUF block types Q8_0/Q4_K/Q5_K/Q6_K,
GGUF IQ codebooks, MXFP4), the vision tower's references, and directional
steering. `#![forbid(unsafe_code)]` is enforced. These exist to be exact,
not fast: `crates/gpu`'s Metal kernels are validated against them, never
the reverse.

## Don't

- Don't hand-roll FP16. This crate DOES hand-roll BF16 (`bf16_to_f32`/
  `f32_to_bf16`, exploiting that BF16 is FP32's upper 16 bits) because no
  Rust crate does it for you, but FP16 storage everywhere in the workspace
  goes through the `half` crate. Mixing the two up is a real, repeated
  mistake class here.
- Don't add a new quantization width by generalizing an existing decoder
  with a parameter. Each width (INT4, 1-bit, 2-bit, GGUF block types, IQ
  codebooks, MXFP4) is measured off a real checkpoint or a ggml oracle and
  gets its own module, because the container, bit order, or table differs
  in ways that read as plausible-but-wrong output rather than an error if
  guessed. `scripts/mlx_1bit_oracle.py` and `scripts/ggml_tables.c` are
  examples of how these were actually settled, not assumed.
- Don't move one of `gdn.rs`'s four FP16 rounding points (conv_out, normed
  q/k, raw conv tail, `y`). They're the exact contract the GPU parity test
  checks against. Moving one makes that test's tolerance meaningless.
- Don't touch `GdnReference::step` for what looks like a no-op change to
  shared flow code. It's what the already-verified qwen3_5/qwen3_6 decode
  chain runs through end to end. `gated_norm_sigmoid` is deliberately a
  standalone sibling rather than a parameter threaded into it, to keep
  edits from silently moving both.
- Don't hand-edit `quant_gguf_iq_tables.rs`. It's GENERATED by
  `scripts/ggml_tables.c`, which probes libggml's `to_float` directly
  rather than transcribing constants: a hand transcription already
  produced a table that was 1.5x too large in every entry once.
- Don't reach for `rms_norm` on the vision tower. `vision.rs`'s tower uses
  `nn.LayerNorm` (subtracts the mean, adds a bias), TWO different GELUs in
  one forward pass, and bidirectional (non-causal) attention. Each of
  those three is a real trap this crate's own tests were written to catch.
