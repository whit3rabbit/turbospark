# App

## Overview
The application shell of the macOS app. It holds the `@main` entry point and SwiftUI scenes (main window, Settings, menu bar extra), the menu-bar command set, the window shell `RootView` (icon rail, top bar, working area, right column, status bar, overlays), the profile-vault unlock gate, window sizing helpers, the fixed keyboard shortcut catalog with its alternate-chord bridge, and the Settings window: sidebar with search, tab enum, a generated control catalog, and the General, Engine, Tools, Memory, Soul and Keyboard Shortcuts panes. Other settings panes (Appearance, Profiles, Models, Safety, MCP, Skills, and so on) live elsewhere and are only mounted from `AppSettingsView.tabContent`. All state lives in `AppModel` and singletons (`ProfileVaultCoordinator`, `AppearanceManager`, `SparkleUpdateController`, `FanController`); this directory binds UI to them.

## Invariants
- `REPLWorkerMain.runIfRequested()` must run before anything else in `main`, and `AppLanguage.writeProcessLanguages` before AppKit reads the language, so a picked language reaches the menu bar [TurboSparkApp.swift:TurboSparkAppMain].
- Bundled fonts are registered both in the delegate's `applicationDidFinishLaunching` and in `TurboSparkApp.init`, before the first view builds, because font pickers filter on `NSFontManager` [TurboSparkApp.swift].
- `applicationWillTerminate` is the authoritative quit hook, and its order matters: `FanController.restoreOnQuitIfNeeded()` first (a pinned fan hold outlives the process), then `AppShutdownCoordinator.onTerminate`, then `LibraryVolumeMonitor.stopAtTermination()` (stopping earlier makes the next volume unmount wait about ten seconds), then `ManagedAssetStore.purgeDecryptedCache()` [TurboSparkApp.swift:applicationWillTerminate].
- Closing the last window quits only when neither `keepServerRunningInBackground` nor `showMenuBarItem` is set, read fresh from `MacAppSettingsFileStore.load()` [TurboSparkApp.swift:applicationShouldTerminateAfterLastWindowClosed].
- The default-maximized frame is adopted once (`TurboSpark.didAdoptMaximizedDefaultWindowFrame`), deferred to the next runloop turn because `NSApp.windows` is empty at launch [TurboSparkApp.swift:adoptMaximizedDefaultFrameOnce].
- Each scene (main, Settings, MenuBarExtra) must inject its own `.appThemed()`, locale and layout direction: scenes do not inherit from `RootView`, and a missing injection renders `ResolvedAppTheme.fallback` [TurboSparkApp.swift:body].
- The window gate: `vaultCoordinator.model` nil shows `ProfileUnlockView`, otherwise `RootView`. Update check and Help commands live outside the vault gate by design (no user data read) [TurboSparkApp.swift:body].
- `MenuBarExtra.isInserted` writes only when the value changed, and the model-dependent menus live in a `Commands` struct with an `@ObservedObject` model. Writing unchanged values or observing from the App `body` caused a 100% CPU loop or frozen menu states [TurboSparkApp.swift:body, TurboSparkModelCommands].
- Menu text must be `Text(_:bundle: .module)` (bare literals resolve against `Bundle.main`, which has no strings in SwiftPM builds). Navigation items derive from `AppModel.AppNavigationSection`, the same source as the rail, the shortcuts pane and `AlternateShortcutBridge` [TurboSparkApp.swift:TurboSparkModelCommands, KeyboardShortcutCatalog.swift:navigation].
- Menu enablement gates mirror each other: an `AlternateShortcutBridge` button must carry the same disabled condition as the menu command it shadows, so an alternate never reaches an action the advertised key would refuse. Its buttons are invisible, zero-size and hidden from accessibility, and are mounted at the window root so they fire while a text field has focus [AlternateShortcutBridge.swift].
- `KeyboardShortcutCatalog` is fixed (no rebinding store). Labels are string-catalog keys and ids are the label, so labels must stay unique [KeyboardShortcutCatalog.swift].
- `RootView.isPanelVisible` is the single predicate for "a panel is on screen" and feeds both the sidebar and the window minimum; the right column has exactly one claimant at a time, and opening one preview or inspector dismisses the others. Toggle shortcuts close an open preview or browser pane rather than flipping an invisible inspector [RootView.swift:isPanelVisible, rightColumnClaimant, toggleModelSettings].
- Dismissing the MCP approval sheet defers (undecided names are absent from registries and re-prompt); only explicit Reject records a decision. The tool-approval sheet presents only after the MCP sheet is gone, since two sheets on one view drop one [RootView.swift:body].
- The vault locks on `sessionDidResignActive` and `screensDidSleep` [RootView.swift:body]. `AppShutdownCoordinator.onTerminate` is set in `onAppear`, and library monitoring starts there, not in `AppModel.init`, so tests never register with the workspace [RootView.swift:onAppear].
- `MainWindowMinimumSize.clamped` never lets a minimum exceed the visible screen, otherwise the window could not be shrunk back [MainWindowMinimumSize.swift:clamped].
- `SettingsWindowFrame` re-applies `.resizable` on attach, once asynchronously, and on every layout pass, because the Settings scene resets the style mask. The default size is applied only when no `NSWindow Frame TurboSpark.SettingsWindow` default exists [SettingsWindowFrame.swift].
- `SettingsControlCatalog.swift` is GENERATED by `scripts/generate-settings-catalog.py` from `.settingsControl(...)` declarations. Edit the declarations, not the catalog. A control named in search must also have a matching `.settingsControl` (the scroll target id is `pane.rawValue + ":" + title`, with remaps in `navigationID` for menu-hosted controls) [SettingsControlCatalog.swift, SettingsControl.swift].
- Settings search trims the query and matches the localized title, the English title and the tab keywords [AppSettingsView.swift:matches].
- Settings changes write through `model.persistSettingsDebounced()` (guardrails mode uses `persistSettings()`), and numeric inputs are clamped at the model boundary (`MacAppSettings.clamp*`, `AppChatCompaction.clampKeepRecent`) [ChatRuntimeSettingsBindings.swift, GeneralSettingsPaneView.swift, EngineSettingsRuntimeSections.swift].
- A protected profile never keeps the conversation recall store: the toggle reads off and is disabled when `vaultCoordinator.isProtected` [GeneralSettingsPaneView.swift:conversationRecallControls].
- Engine pane "Resolved" rows read back what the loaded session reported (`session.info`: `kvBits`, `anePrefill`, `expertSlotsWiring`, `expertResidency`) rather than restating the setting; the server address and auth rows come from `model.serverInfo`. The reasoning picker uses the checkpoint's own levels, with the full union only when no session is open [EngineSettingsRuntimeSections.swift].
- Each pane keeps `Section`s as separate computed properties because one big `Form` expression exceeded the macOS 14 SDK type-checker budget on the CI toolchain [EngineSettingsPaneView.swift:body, GeneralSettingsPaneView.swift].
- Memory ledger raw values (`MemoryClaimStatus`, kind, confidence) are persisted in the encrypted profile and must not change: translation happens in `MemoryClaimText`. `MemoryEditSheet` keeps the sheet and draft open when a save fails [MemoryEditSheet.swift, MemorySettingsPaneView.swift:body].
- The prompt preview in the Memory pane shows the exact prompt text and is intentionally untranslated, and approved-only [MemorySettingsPaneView.swift:promptPreview].
- Tool profiles: built-in profiles are read-only (Duplicate to edit). A selection containing every tool is stored as `allowedTools == nil` so tools added later still reach the profile [ToolsSettingsPaneView.swift:setTool, editorSection].
- The unlock view clears the passphrase field as soon as it is submitted and attempts system authentication only once per appearance [ProfileUnlockView.swift:unlock, task].

## Side Effects
- UserDefaults: `TurboSpark.didAdoptMaximizedDefaultWindowFrame` (set once) [TurboSparkApp.swift:adoptMaximizedDefaultFrameOnce]; AppStorage keys `TurboSpark.chatSidebarVisible`, `TurboSpark.inspectorVisible` and `AppLanguage.storageKey` [RootView.swift, TurboSparkApp.swift]; AppKit window autosave `NSWindow Frame TurboSpark.SettingsWindow` read and written via `setFrameAutosaveName` [SettingsWindowFrame.swift].
- Settings files and persistence: `MacAppSettingsFileStore.load()` at window close [TurboSparkApp.swift]; `persistSettingsDebounced()` and `persistSettings()` throughout the panes.
- Keychain and vault: the unlock view calls `ProfileVaultCoordinator.unlock(passphrase:)` and `unlockWithSystemAuthentication()` (Touch ID or login password) [ProfileUnlockView.swift]. `ProfileVaultCoordinator.lockNow()` runs on session resign and screen sleep [RootView.swift]. The server API key field persists through the model's settings write [EngineSettingsRuntimeSections.swift:inProcessServerSection].
- Process-wide state: `AppLanguage.writeProcessLanguages` mirrors `AppleLanguages` [TurboSparkApp.swift]; `NSApp.setActivationPolicy(.regular)` and `NSApp.activate` at launch [TurboSparkApp.swift]; `EngineImageTranscoder.purgeLegacyPersistentCaches()` at launch.
- Quit-time: fan restore, `AppShutdownCoordinator`, volume monitor stop, `ManagedAssetStore.purgeDecryptedCache()` (deletes decrypted attachment cache under `~/Library/Caches`) [TurboSparkApp.swift:applicationWillTerminate].
- NotificationCenter: posts `.toggleChatSidebar`, `.toggleInspector`, `.showChatSearch`, `.focusPrompt` from menu commands [TurboSparkApp.swift]; observes `.openSettingsTab`, those same names in `RootView`, and the workspace `sessionDidResignActive` and `screensDidSleep` notifications [AppSettingsView.swift, RootView.swift].
- Workspace: opens documentation and issue URLs with `NSWorkspace.shared.open` [TurboSparkApp.swift]; `Link` to the ThermalForge repository in the Engine pane [EngineSettingsPaneView.swift]; `startLibraryMonitoring()` registers workspace volume observers [RootView.swift:onAppear].
- Server and engine control: `model.startServer()`, `model.stopServer()`, `model.loadModel()`, `reloadModel()`, `unloadModel()`, `ModelLocationPicker.choose`, `switchToProfile` (save-and-relaunch), `FanController.keepFansPinnedOnQuit`, and the memory ledger (`MemoryLedgerStore.shared` edit, forget, approve, dismiss, embedding rebuild, clear) [TurboSparkApp.swift, EngineSettingsPaneView.swift, EngineSettingsRuntimeSections.swift, MemorySettingsPaneView.swift].
- Timers and tasks: a 150 ms sleep before scrolling to a highlighted settings control [AppSettingsView.swift:body]; async embedding index rebuild in `Task` [MemorySettingsPaneView.swift:profileSection].
- Sparkle updates are owned by the child directory, started from `TurboSparkApp.init` and no-op outside a real `.app` bundle [Updates/SparkleUpdateController.swift:SparkleUpdateController].
- No direct network or FFI calls in this directory.
