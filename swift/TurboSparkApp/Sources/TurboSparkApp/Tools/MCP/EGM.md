# Tools/MCP

## Overview
The Model Context Protocol client side of the app. It holds the persisted server configuration model (`McpServerConfig` and its transports), importers that read MCP definitions from project files and from other agents' global configs, a JSON-RPC 2.0 stdio client with persistent per-server sessions, a process-wide cache of discovered tools, the editor validation and approval-summary values the UI renders, and the model-facing tool definitions for MCP resources. Only the stdio transport is implemented. The SSE transport and the `resources/list` and `resources/read` requests deliberately throw an explicit "not implemented" error instead of returning a fabricated success. [McpClientEngine.swift:McpClientEngine] [McpResourceExecutor.swift:McpResourceExecutor]

- Tool cache: `McpToolCatalogCache.shared` (`tools(forServerName:)`, `isStale(for:)`, `setTools`, `removeServer(named:)`, `removeAll`, `refreshEnabled(servers:workingDirectory:)`) with an injectable `Discovery` closure. [McpToolCatalogCache.swift:McpToolCatalogCache]
- Importers: `ProjectMcpDetector` (`detectInProject`, `parseConfigFile`, `parseConfigData`, `expandVariables`, `allowedEnvironmentVariableKeys`) with `DetectedProjectMcpFile`; `ExternalAgentMcpReader.discoverSources(home:)` with `ExternalAgentMcpSource` (Claude Code `.claude.json`, Cursor, Gemini CLI JSON, and Codex `config.toml`). - Login-shell PATH (module-internal): `LoginShellPath.resolved()`, `cached`, `parse`, `defaultShell`, `capture`. [LoginShellPath.swift:LoginShellPath]

## Invariants
- Server NAME, trimmed and lowercased, is the identity key, not `id`. The tool registry, the permission engine, the catalog cache and session retirement all resolve by `normalizedName`; duplicates are refused by form validation. [McpServerSpec.swift:nameIsTaken] [McpServerFormValidation.swift:refusal]
- `autoApprove` is forced false for every config read from disk (project files, external agent configs, Codex TOML), so a cloned repository cannot grant itself silent tool execution. Imports expand only `${workspaceFolder}`, `${projectRoot}`, `${cwd}` and `${env:KEY}` for PATH, HOME, LANG and TMPDIR; no other host variable is expanded (credential exfiltration guard). [ProjectMcpDetector.swift:parseConfigData] [ProjectMcpDetector.swift:expandVariables] [ExternalAgentMcpReader.swift:codexServerConfig]
- `childEnvironment` is an allowlist and must stay one: baseline keys PATH, HOME, LANG, TMPDIR, then named `envPassthrough` keys, then declared `env` (later wins). A passthrough key absent from the parent is omitted, not set empty. Relative PATH entries are dropped everywhere (the child's cwd is the project root). [McpClientEngine.swift:childEnvironment]
- `LoginShellPath` lets only `PATH` out of the login shell, runs with cwd HOME (never the project root), a dumb TERM and a minimal forwarded env, drops relative entries, trusts a shell only if `/etc/shells` lists it, and caches a failed capture as nil so a broken rc costs one timeout per run. It is not run at launch, only on the first stdio spawn. [LoginShellPath.swift:capture] [LoginShellPath.swift:defaultShell] [LoginShellPath.swift:resolved]
- An unresolvable command is refused by name in `spawnStdioServer`; there is no `/usr/bin/env` fallback. A server's own `cwd` beats the caller's default, an empty or unset `cwd` falls through, and a relative `cwd` is relative to the project. [McpClientEngine.swift:spawnStdioServer] [McpClientEngine.swift:resolveWorkingDirectory]
- Writes to child stdin use `write(contentsOf:)` (throwing) because the legacy overload raises an uncatchable Objective-C exception on EPIPE. Child termination uses `ProcessExecutor.terminateAndReap` (SIGKILL escalation), never a bare SIGTERM. Stderr is drained into a 4096-byte tail so a chatty child cannot block on a full pipe. [McpClientEngine.swift:sendJsonRpc] [McpClientEngine.swift:StderrTail]
- `tools/call` retries at most once, and only on `McpSessionError.closedBeforeSend` (nothing reached the server); a request that was written is never replayed. A timeout or cancellation tears the whole shared session down and kills the process tree synchronously, so a caller never sees cancellation while the operation can still run. [McpClientEngine.swift:callToolViaStdio] [McpStdioSession.swift:timeOut] [McpStdioSession.swift:cancel]
- Session identity is `McpSessionKey` (all config fields plus working directory, in memory only). A same-name session with a different key is retired (finishes in-flight calls, then exits). Idle sessions tear down after 300 s. Requests from the server get `ping` answered and everything else method-not-found. [McpClientEngine.swift:session] [McpStdioSession.swift:handleLine] [McpStdioSession.swift:idleFired]
- `McpServerConfig` decoding: `transport` is intentionally not tolerant (a row with no readable transport fails so `decodeLossyArray` drops that one server), while other fields default. Fields added later use `decodeIfPresent` with defaults. Preserve this when changing the persisted shape. [McpServerSpec.swift:init(from:)] [McpServerSpec.swift:McpTransportSpec]
- Discovery follows `nextCursor` for at most 20 pages and uses JSON-RPC ids 1 to 21. Only the tool-annotation keys `readOnlyHint` (or short `readOnly`), `destructiveHint`, `idempotentHint`, `openWorldHint`, `title` are read; annotations are hints the permission engine does not trust over name heuristics. [McpClientEngine.swift:discoverToolsViaStdio] [McpServerSpec.swift:McpToolAnnotations]
- Catalog cache entries invalidate by transport equality, have no TTL (refresh is event-driven), and in-flight request identity (`UUID`) is revoked by removal or reconfiguration so a late completion cannot publish. [McpToolCatalogCache.swift:refreshTasks] [McpToolCatalogCache.swift:complete]
- Approval UI must show the full argv untruncated, show loader-style env values (`NODE_OPTIONS`, `DYLD_*`, `LD_*`, `PATH`, and similar) and mask other env values. [McpApprovalSummary.swift:McpApprovalSummary]
- Form validation: an unparseable endpoint blocks saving and is never replaced with an invented default URL. The English `message` is pinned by tests and the editor shows `localizedMessage`. [McpServerFormValidation.swift:parsedEndpointURL]
- The SSE transport and the resource list or read executors must keep throwing honest errors until implemented; they must not return a success string. [McpClientEngine.swift:discoverToolsViaSSE] [McpResourceExecutor.swift:notImplementedMessage]

## Side Effects
- Process spawn: stdio MCP server children via `Process` with piped stdin, stdout, stderr and `readabilityHandler` callbacks on GCD threads; login-shell probe (`-ilc` for zsh and bash, `-lc` otherwise) through `ProcessExecutor.run` with a 4 s timeout and 64 KiB output cap. [McpClientEngine.swift:spawnStdioServer] [LoginShellPath.swift:capture]
- Process-wide state: `McpSessionProcessRegistry` pid set (killed on app quit by `killAllSessionProcessesNow`), the `McpToolCatalogCache.shared` singleton, and the `LoginShellPath` cache. [McpStdioSession.swift:McpSessionProcessRegistry] [LoginShellPath.swift:Cache]
- Tasks and timers: per-request timeout tasks, idle tasks, a reader task per session, 30 ms polling in the one-shot discovery path, and background `Task`s from `refreshEnabled`. [McpStdioSession.swift:request] [McpClientEngine.swift:readJsonRpcResponse] [McpToolCatalogCache.swift:refreshTasks]
- Disk reads: project config files (`.mcp.json`, `opencode.json`, `.opencode/opencode.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, `.claude/mcp.json`, `.agents/mcp_config.json`, `.gemini/mcp.json`), home configs (`.claude.json`, `.cursor/mcp.json`, `.gemini/settings.json`, `.codex/config.toml`), `/etc/shells`, `~/.nvm` directories, and the passwd entry. [ProjectMcpDetector.swift:candidateLocations] [ExternalAgentMcpReader.swift:discoverSources] [McpClientEngine.swift:nvmNodeBinDirectory]
- `McpResourceExecutor` reads `GlobalMcpFileStore.load()` and `AppToolCatalogMcp.resolvedServers`, which are defined elsewhere. [McpResourceExecutor.swift:listResources]
- Network, Keychain, UserDefaults, NotificationCenter, FFI: None.
