# Tools/File

## Overview
The file-oriented model tools: read, write and edit payload types and OpenAI tool schemas, plus the executors for Snip, NotebookEdit, MultiEdit (atomic multi-file), ApplyPatch (unified diff), SendUserFile, and the Syntext-backed `grep_search`. It also holds the shared safety state that stops stale writes (`FileSnapshotStore`), the search path policy that keeps indexed and unindexed search hiding the same files (`GrepPathPolicy`), and the single funnel that reports produced files to a chat's artifact list (`ArtifactRegistrar`). The FileRead, FileWrite, FileEdit, Glob and Grep executors themselves are not in this directory; only their input and output types and schemas are. Executors resolve paths through `AppToolRegistry.resolveSecurePath` and write paths through `AppToolSandbox.validateWritePath`, both defined elsewhere. [FileReadWriteTools.swift:FileReadWriteToolDefinitions] [FileSearchTools.swift:FileSearchToolDefinitions]

## Invariants
- Stale-write protection is snapshot based: every read or write records a SHA-256 of the bytes, and edit and multiedit refuse a file whose disk hash differs (`isStale`). `isStale` answers false for an untracked file on purpose, so a destructive write over an existing file the model never read must also ask `isTracked`. Caps: 512 tracked files and 512 backups, evicted oldest first. `reset()` must clear snapshots and backups when the project changes. [FileSnapshotStore.swift:isStale] [FileSnapshotStore.swift:isTracked] [FileSnapshotStore.swift:maximumTrackedFiles]
- Undo is single slot: a backup records a path's prior content, and `backupMatchesCurrent` is true only while the file still hashes to the edit's own post-write snapshot, so a later write or outside edit blocks a silent revert. The post-edit hash is captured by the next `recordSnapshot` for that path. [FileSnapshotStore.swift:recordBackup] [FileSnapshotStore.swift:backupMatchesCurrent]
- `recordSnapshot` should take content the caller already holds rather than re-reading the file. [FileSnapshotStore.swift:recordSnapshot]
- MultiEdit is three-phase and atomic: phase 1 validates every edit (secure path, write sandbox, exists, not stale, `old_string` found, unique unless `replace_all`) against content that accumulates across edits to the same file; phase 2 records backups; phase 3 writes each file atomically and rolls back every already-written file if one write fails. Failure before phase 3 writes nothing. `edits` falls back to `edits_json`; a missing `file_path` accepts `path`. [MultiEditExecutor.swift:execute]
- ApplyPatch is two-phase: all hunks are applied in memory (context and removal lines must match exactly, hunks must be in order and in range, CRLF files are normalized and restored), then `commit` writes and restores prior bytes on failure. A patch with no operations throws instead of reporting success; `*** Begin Patch` is unsupported. A `/dev/null` source refuses to overwrite an existing file. A delete is refused if the file was read and has since changed; an untracked file still deletes. Updates have no snapshot gate because context verification is stronger. After commit, snapshots are recorded or removed per path. [ApplyPatchExecutor.swift:apply] [ApplyPatchExecutor.swift:commit] [ApplyPatchExecutor.swift:applyHunkLines]
- Hunk parsing treats every line inside a hunk's declared counts as body (so `--- x` removals are not mistaken for headers), except a `---`, `+++`, `@@` run, which always starts a new file even if counts are miscounted. Per-file state is reset on every exit of `flushCurrentFile`. [ApplyPatchExecutor.swift:apply]
- NotebookEdit: replace and delete require `cell_id` or `cell_index` (no silent default to the first or last cell); insert with an id inserts after that cell; new cells get fresh unique ids; replace keeps the cell's type unless `cell_type` is given (only code cells get outputs and an execution count); a stale-on-disk or over-16-MB notebook is refused; writes are atomic, validated by `validateWritePath`, and re-snapshot afterwards. [NotebookEditExecutor.swift:execute]
- Snip and MultiEdit read through `AppFileReadLimits.readTextFile`, so oversized files are refused before loading. [SnipExecutor.swift:execute] [MultiEditExecutor.swift:execute]
- Search path policy: the indexed (Syntext) and unindexed searches must hide the same files. It excludes `.git`, `node_modules`, `target`, `.build` at any depth, hidden path components below the requested scope, and anything `ToolRiskClassifier.isSensitivePath` flags (checked with and without a leading slash). `grep` also enforces `scope` itself and over-fetches (limit times 4, between 200 and 2000) because the policy hides matches after Syntext counts them. Output caps: 500 results, 10 context lines. [GrepPathPolicy.swift:allows] [SyntextCodeSearchTool.swift:grep]
- Syntext index lifecycle: one build at a time process-wide (`SyntextBuildQueue`); only the active project keeps a mmap handle; a search never waits on a build and throws `SyntextIndexNotReady` so the registry falls back to the unindexed scan; a failed load is not retried for 60 s; `generation` counters stop a stale load from installing; changes with no handle are buffered (max 512 paths, then a rebuild) and replayed; an overlay-full commit (code 9) drops the handle and rebuilds; lock conflicts retry three times; activation tokens older than the newest are dropped; `deleteIndex` waits for an in-flight build before removing the directory. [SyntextCodeSearchTool.swift:loadIndex] [SyntextCodeSearchTool.swift:commitPending] [SyntextCodeSearchTool.swift:searchableIndex] [SyntextCodeSearchTool.swift:activate]
- Index directory name is a 16-byte SHA-256 prefix of the resolved root path (fixed length, stable across spellings); tests use the redirected machine root, never the real Caches folder. [SyntextCodeSearchTool.swift:defaultIndexDirectory] [SyntextCodeSearchTool.swift:cacheRoot]
- Artifact registration: only the pure policy `artifactCandidates` decides, and `report` must be called from inside the success path of `execute`, never its catch. Sent-to-user, plan and image-generation files always qualify; a `fileWrite` qualifies only for Markdown or HTML extensions, read from the panel's own extension sets. A nil chat ID means register nothing and never fall back to the selected chat. [ArtifactRegistrar.swift:artifactCandidates] [ArtifactRegistrar.swift:report]
- JSON coding keys (`file_path`, `validate_command`, and so on) are part of the model-facing contract and the tool schemas must stay in step with them. [FileReadWriteTools.swift:FileReadInput] [FileSearchTools.swift:GrepInput]

## Side Effects
- Disk writes: atomic file writes and `removeItem` for MultiEdit, ApplyPatch (with rollback) and NotebookEdit; ApplyPatch creates parent directories. [MultiEditExecutor.swift:execute] [ApplyPatchExecutor.swift:commit] [NotebookEditExecutor.swift:execute]
- Disk reads and directory management for the Syntext index under the Caches folder (`TurboSpark/syntext`), including removing the legacy `com.turbospark.app/syntext` folder once per run in the background and deleting an index directory on request. [SyntextCodeSearchTool.swift:removeLegacyCache] [SyntextCodeSearchTool.swift:deleteIndex]
- FFI: calls into the `Syntext` module (`SyntextIndex` open, build, `searchAsync`, `searchFreshAsync`, `notifyChange`, `notifyDelete`, `commitBatch`, `stats`) on detached utility-priority tasks. [SyntextCodeSearchTool.swift:loadIndex] [SyntextCodeSearchTool.swift:grep]
- Tasks and timers: 1.5 s debounced quiet-commit task, background load tasks, detached build tasks. [SyntextCodeSearchTool.swift:scheduleQuietCommit]
- Global hooks assigned by app code elsewhere: `SendUserFileExecutor.onFileSent` and `ArtifactRegistrar.onArtifactsProduced` (static mutable closures, outbound notifications). [SendUserFileExecutor.swift:onFileSent] [ArtifactRegistrar.swift:onArtifactsProduced]
- Shared process state: `FileSnapshotStore.shared`, `SyntextIndexManager.shared`, `SyntextBuildQueue.shared`. [FileSnapshotStore.swift:shared] [SyntextCodeSearchTool.swift:SyntextIndexManager]
- Network, Keychain, UserDefaults, NotificationCenter, process spawn: None in this directory.
