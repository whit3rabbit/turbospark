# Tools/Repl

## Overview
The JavaScript REPL subsystem. Model-written JavaScript runs inside a JavaScriptCore context that lives in a separate worker child process: the packaged app executable re-entered with `--turbospark-js-repl-worker --serve`. The app side (`REPLWorkerProcess`) supervises that child over newline-delimited JSON on stdin and stdout. The worker side (`REPLWorkerMain` and `REPLWorkerContext`) owns one persistent `JSContext`, so top-level bindings persist across calls. Scripts see only a frozen `console`, `repl.fs` (a rooted file facade that forwards bounded requests to an app-side broker) and `repl.emitImage`. A bounded token-based parser lowers top-level `await` programs to an async wrapper, because classic-script evaluation cannot contain `await`. The same worker entry also hosts a one-shot codemode serve path (`--codemode-serve`) whose sandbox and wire types live outside this directory. [REPLWorkerMain.swift:REPLWorkerMain] [REPLScriptLowering.swift:REPLBoundedScriptParser]

[REPLSessionTypes.swift:REPLLimits] [REPLSessionTypes.swift:REPLCallResult]
- Supervisor (app side): `REPLWorkerProcess(executableURL:configuration:limits:)`, `evaluate(code:settlementTimeout:)`, `terminateAndWait(grace:)`, `isRunning`, `serveArguments`, `defaultExecutableURL()`. [REPLWorkerProcess.swift:REPLWorkerProcess]
- Worker entry: `REPLWorkerMain.isWorkerInvocation(_:)`, `runIfRequested(arguments:writeOutput:)` (dispatches `--serve`, `--codemode-serve`, the codemode probe argument and `--smoke`), plus the constants `workerModeArgument`, `serveArgument`, `serveCodemodeArgument`, `maximumTransportBytes`. [REPLWorkerMain.swift:REPLWorkerMain]
- Worker context: `REPLWorkerContext` (`evaluate`, `evaluateWithThreadStatus`, `defaultSettlementDeadline`, static `boundText` and `compactOutputEvents`), `REPLCallCapture` (lock-guarded bounded console, image and exception capture), `REPLWorkerEvaluation`. [REPLWorkerContext.swift:REPLWorkerContext] [REPLWorkerContext.swift:REPLCallCapture]
- Host facade: `REPLHostFacade` with `installConsole`, bridge-then-seal installers (`installFileRequestBridge`, `installImageEmitterBridge`, `sealReplSurface`) and single-capability convenience installers (`installFileSystem`, `installImageEmitter`); `REPLConsoleSink`. [REPLHostFacade.swift:REPLHostFacade]
- File broker: `REPLFileAccessBroker` (`perform(_:chatID:)`, `canonicalTarget(for:under:)`, `maximumPathCharacters`, `maximumTransferBytes`), `REPLFileGrantSource`, `REPLFileAccessRequest` and `Operation`, `REPLFileAccessResult`, the `REPLFileRequestChannel` protocol with `REPLInProcessFileChannel` and fail-closed `REPLNoAccessFileChannel`. [REPLFileAccessBroker.swift:REPLFileAccessBroker]
- Script lowering: `REPLClassicScriptSyntax.check`, `REPLSettlementBox`, `REPLLoweredWrapperBuilder.build`, `REPLBoundedScriptParser.parse` with `REPLBoundedLexer`, `REPLBoundedProgram`, `REPLBoundedStatement`, `REPLLexToken`, `REPLBoundedParseOutcome`. [REPLScriptLowering.swift:REPLLoweredWrapperBuilder]

- Child EGM.md files: None (no subdirectories).

## Invariants
- Per-call decision order in `REPLWorkerContext`: empty script is `parseError`; `JSCheckScriptSyntax` success evaluates natively; otherwise the bounded parser decides. A parse that does not use top-level await reports the native syntax message as `parseError`. Unsupported syntax that uses await returns `unsupportedSyntax` before anything evaluates. Parse errors, unsupported syntax and ordinary exceptions never reset the session. [REPLWorkerContext.swift:evaluateOnWorkerQueue]
- All JSContext creation, facade installation, evaluation and result rendering stay on the single private serial queue `com.turbospark.repl.worker-context`. File responses are delivered on a separate serial queue so a pending top-level await can still be serviced; `REPLCallCapture` is lock-guarded for that reason. [REPLWorkerContext.swift:REPLWorkerContext] [REPLHostFacade.swift:fileResponseQueue]
- The `repl` object can be sealed only once. Contexts with several capabilities must install the bridges and then call `sealReplSurface` exactly once, before any script runs. A second seal is a no-op because the temporary bridge globals are deleted. `console`, `repl`, `repl.fs` and every method are non-writable, non-configurable and frozen. [REPLHostFacade.swift:sealReplSurface] [REPLHostFacade.swift:replSurfaceInstallationScript]
- Lowered declarations become writable global properties (var-like). const enforcement, temporal dead zones and redeclaration errors are not preserved, and a native lexical binding of the same name shadows a lowered property. The parser rejects destructuring, multi-declarator declarations, labels, top-level return and import or export. A final compound statement completes as undefined. Function declarations are installed first to mimic hoisting. [REPLScriptLowering.swift:REPLLoweredWrapperBuilder] [REPLScriptLowering.swift:classifyTokens]
- The settlement deadline cannot terminate the context in process; only the supervisor killing the process ends a wedged call (the process restart policy is not in this directory). [REPLWorkerContext.swift:evaluateLowered]
- File access fails closed and is re-evaluated per operation: no chat ID, no roots, an over-long path (4096 characters), an over-limit payload or a path outside every currently granted root all deny. Workers never receive grants or identity. The default channel is `REPLNoAccessFileChannel`. [REPLFileAccessBroker.swift:perform]
- Path containment resolves symlinks on both the root and the candidate (including ancestors of a not-yet-existing write target) before a prefix compare; paths beginning with `~` are rejected; the final component is opened with `O_NOFOLLOW` (`O_DIRECTORY` for list). Error text names only the last path component so granted roots do not leak. [REPLFileAccessBroker.swift:canonicalTarget] [REPLFileAccessBroker.swift:ioFailure]
- `emitImage` accepts only PNG or JPEG judged by magic bytes, never by the label; the file name is `repl-image-<UUID>.<ext>` and never derives from model input; payloads over `maximumImageBytes` are rejected (an early base64 length check precedes decoding). [REPLHostFacade.swift:emitImagePayload]
- Output is bounded as it arrives (head plus rolling tail with a dropped-character count) and again in `makeResult` with head two thirds, tail one quarter of the cap. Completion and error text get the same bound; the truncation flag is computed on the Swift side. [REPLWorkerContext.swift:REPLCallCapture] [REPLWorkerContext.swift:boundText]
- Wire protocol: one init line, then one evaluate line per request, one result line per request, in write order. The worker serves one request at a time (it blocks on a semaphore), so result order equals request order. The supervisor registers the continuation before writing the line, FIFO-serializes callers through an `AsyncStream` mailbox, and rejects scripts over `maximumRequestBytes` locally. A result line with an unknown id (line-level worker failure, id -1) resolves the oldest pending caller. The worker also enforces a 4 MiB transport limit per line and applies the script limit to the code bytes, not the wire line. [REPLWorkerProcess.swift:receive] [REPLWorkerMain.swift:serveRequests]
- The worker must read stdin with raw POSIX `read` (Foundation `read(upToCount:)` blocks until full length on a pipe). [REPLWorkerMain.swift:serveRequests]
- Codemode serve path: confines the process with `CodemodeWorkerSandbox.apply()` before any JavaScript context exists and fails closed with a crash line if confinement fails; serves exactly one execution per process and exits after the terminal line. [REPLWorkerMain.swift:serveCodemodeRequests]
- `signal(SIGPIPE, SIG_IGN)` is set in the supervisor so a closed pipe surfaces as an error. Worker stderr goes to the null device. [REPLWorkerProcess.swift:init]

## Side Effects
- Process spawn: `Process` launches `Bundle.main.executableURL` with `--turbospark-js-repl-worker --serve`; stdin and stdout pipes; SIGTERM after a 2 second grace on `terminateAndWait`; `deinit` terminates a still-running child. [REPLWorkerProcess.swift:init] [REPLWorkerProcess.swift:terminateAndWait]
- Disk (worker, via broker): `open`, `fstat`, read, write with `O_CREAT | O_TRUNC` (mode 0644), and directory listing inside granted roots. [REPLFileAccessBroker.swift:read] [REPLFileAccessBroker.swift:write] [REPLFileAccessBroker.swift:list]
- Disk: image emission creates the artifact directory and writes `repl-image-<UUID>` files atomically; the default directory is `AppStorageRoot.subdirectory("repl-artifacts")`. [REPLHostFacade.swift:emitImagePayload] [REPLWorkerContext.swift:init]
- Threads and tasks: dispatch queues for write (`com.turbospark.repl.worker-write`), file response and worker context, a mailbox consumer `Task`, `Task.detached` per evaluate, a 5 ms sleep polling loop while waiting for settlement, and `readabilityHandler` plus `terminationHandler` on the child pipes. [REPLWorkerProcess.swift:init] [REPLWorkerContext.swift:evaluateLowered]
- Process exit: the worker calls `exit(EXIT_FAILURE)` on a failed smoke check and `exit(EXIT_SUCCESS)` after a codemode execution. [REPLWorkerMain.swift:runIfRequested] [REPLWorkerMain.swift:serveCodemodeRequests]
- No Keychain, UserDefaults, NotificationCenter, network or FFI use in this directory.
