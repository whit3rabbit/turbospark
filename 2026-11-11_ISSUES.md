# Issues found while generating and checking EGM contracts

Date: 2026-11-11. Scope: what the EGM bootstrap and drift checks surfaced about the code itself, separated from doc-only drift (see `2026-11-11_DRIFT_REPORT.md`).

Status key:
- **Confirmed**: I read the cited lines myself.
- **Worker-reported**: a subagent that read the files reported it. I have not re-checked it.

Nothing here is fixed. Severity is my rough judgment, not a rating from a tool.

## Security relevant

### S1. Web search providers skip the SSRF destination validator
- Status: Confirmed in part. `HttpRequestDestinationValidator` is referenced only from `HttpRequestExecutor.swift` and `WebFetchExecutor.swift`. `fetchLimited` in `WebSearchExecutor.swift` calls `session.bytes(for:)` directly with no validation. Worker-reported: Tavily uses its own ephemeral session, there is no redirect or connected-address check on the search path, and SearXNG takes a user-supplied base URL.
- Where: `swift/TurboSparkApp/Sources/TurboSparkApp/Tools/Web/WebSearchExecutor.swift:fetchLimited`, `searchSearXNG`.
- Why it matters: `Web/EGM.md` claimed all outbound requests share one SSRF defense. A user-configured SearXNG URL pointing at localhost or a metadata address would not be refused.

### S2. Hook user-config values are substituted raw into the shell command
- Status: Confirmed. `AppHookCommandRunner.swift` does `commandText.replacingOccurrences(of: "${user_config.\(k)}", with: v)` for every non-sensitive option, with no quoting or escaping. Worker-reported: sensitive options become env references instead, and every option is also exported as `TURBOSPARK_OPTION_*` and `CLAUDE_PLUGIN_OPTION_*`.
- Where: `Tools/Hooks/AppHookCommandRunner.swift:executeCommandHook`.
- Why it matters: an option value containing shell metacharacters changes the command that runs. Impact depends on who can set option values.

### S3. Hook `if` condition is fail-open
- Status: Worker-reported.
- Where: `Tools/Hooks/AppHookMatcher.swift:matchesCondition`.
- Detail: a condition without `(` and a trailing `)` is ignored and matches everything. The tool-prefix match falls back to a case-insensitive substring match.
- Why it matters: a mistyped condition runs the hook on every call instead of none.

### S4. Custom-tool trust is not rechecked in the executor, and the fingerprint ignores parameters
- Status: Confirmed in part. `CustomToolTrustStore.fingerprint` hashes projectPath, sourcePath, lowercased name, effective category and the encoded `execution`. It does not include `parameters`, `toolDescription` or `isEnabled`. `CustomToolExecutor.swift` contains no trust reference. Not verified: whether `AppToolRegistry` checks trust before calling `CustomToolExecutor.execute` at `AppToolRegistry.swift:967`.
- Why it matters: editing a project-local tool's declared parameters changes which model arguments reach the environment or substitution, without invalidating trust.
- Worker-reported, related: script substitution runs once per argument over a dictionary, so one argument's value containing another's `{{k}}` or `${k}` marker can be re-substituted in dictionary order. Tool names are not sanitized before use in `<name>.json` and `custom_<name>_<id>.sh`.

### S5. Terminal auto-approve classifier checks only the head word
- Status: Worker-reported.
- Where: `Tools/Terminal/TerminalCommandClassifier.swift:isAutoApprovable`.
- Detail: only the head word, interpreter inline flags and the `git` subcommand are checked, so `find ... -delete`, `awk 'system(...)'` and `git push --force` pass this layer. `python`, `python3`, `node` and `mkdir` are on the build list. Code comments say `ToolRiskClassifier` covers the rest.
- Related worker-reported, `Tools/Core`: the "not a recognized read-only or build command" branch of `assessTerminalCommand` returns `.high` with `hardGated` nil, a soft ask. `assessMcpTool` also returns a soft `.high` for MCP calls whose arguments hit `isSensitivePath`. `Core/EGM.md` said both were hard-gated.

### S6. REPL transport has no cap on an unterminated line
- Status: Worker-reported.
- Where: `Tools/Repl/REPLWorkerMain.swift:serveRequests`.
- Detail: the 4 MiB limit is checked only after a newline-terminated line is buffered. The codemode loop checks `CodemodeWire.maximumLineBytes` against `buffer.count` first.
- Mitigating: the REPL subsystem is not reachable from the tool executor today (see C3).

## Correctness and resource bugs

### B1. `strip_thinking` leaks memory per call
- Status: Confirmed. `crates/audio/src/stt/moss_music/mod.rs:1029` does `working = Box::leak(stripped.into_boxed_str())` whenever the text contains a closed `<think>...</think>` block.
- Why it matters: one leaked string per such transcription call, for the life of the process. A long-running server leaks proportionally to use.

### B2. Duplicate error codes in one domain
- Status: Confirmed in part. Code 60 under domain `TurboSparkTool` appears in `CronScheduler.swift` (lines 445, 460, 595) and `AutomationExecutors.swift:35`. Code 35 appears in `BatchToolExecutor.swift:109` and `PlanningInteractiveExecutors.swift:384`. Worker-reported but not confirmed: the second user of code 35 is `SendFeedbackExecutor`, and codes 61 and 62 are shared by Config and cron.
- Why it matters: callers that branch on the code cannot tell the errors apart.

### B3. `TaskOutput` ignores `block` and `timeout`, and `deleted` status is never applied
- Status: Worker-reported.
- Where: `Tools/Tasks/TaskManager.swift:executeOutput`, `updateTask`.
- Detail: the schema requires `block` and `timeout` but the executor ignores both and cannot read a background shell or subagent. The schema advertises a `deleted` status that never removes the task. Task IDs are the first 8 characters of a UUID.

### B4. Background-shell limit of 20 is soft, and an ID is consumed on refused launches
- Status: Worker-reported. `BackgroundShellManager.swift:launch` checks the count, releases the lock, then inserts.

### B5. Guardrails casing mismatch
- Status: Worker-reported. Rescue accepts tool names case-insensitively but `inspect` looks up `specsByName[call.name]` case-sensitively, so a rescued `Read` for a tool named `read` returns `.retry` with "Unknown tool".
- Where: `Tools/Guardrails/ForgeGuardrailsEngine.swift:inspect`.

### B6. Smaller worker-reported items
- `NotebookEdit` replaces without `cell_type` convert a markdown cell to code and clear outputs. It re-serializes the notebook with sorted keys, reordering the file, and has no staleness check or size limit. `Tools/File/NotebookEditExecutor.swift:execute`.
- `ApplyPatchInput` decodes alternative spellings only through a `[String: String]` decode. One non-string value (for example `validate_timeout_ms` as an Int) makes `patchText` empty. `validate_command` and `validate_timeout_ms` are decoded but unused.
- `MultiEdit` phase 3 writes files in dictionary order, and backups from phase 2 are not discarded if phase 3 fails.
- `Cron`: a missed one-shot job is deleted, not retried. `jobs = archive` is assigned outside the lock in `load`.
- `Planning`: a cancel arriving before `waitForAnswer` registers its continuation does not dismiss the question. `ProposeSkills` writes immediately with no validation of `skillMd`, ignores `kind: "improvement"`, and can report "Successfully saved 0 proposed skill(s)".
- `Custom`: HTTP non-2xx responses are returned as successes. `.http` effective category collapses declared `.fileWrite`, `.mcp` and `.automation` to `.web`.
- `Hooks`: HTTP hooks can never block, since a non-2xx status parses as exit 1. Options and custom-hooks files may not be written atomically.
- `MCP`: relative `PATH` entries are filtered only when `executableDirectory` is set. A declared `PATH` is applied unfiltered.
